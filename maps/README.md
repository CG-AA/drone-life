# Maps

A map is a normal [Tiled](https://www.mapeditor.org/) file (`.tmj` JSON, or `.tmx`)
authored in **isometric** orientation with **2:1 tiles** (e.g. 64×32). Configure it
with `MAP=example.tmj` (a name in this folder, or an absolute path). No `MAP` → the
built-in ±100 m arena, exactly as before.

`example.tmj` + `tiles.png` are generated by `tools/gen_example.py`; open them in
Tiled to see the conventions, edit, save. Keep tileset images next to the map (this
folder is served at `/maps/` for the viewer).

## Map properties

| property          | meaning                              | default |
|-------------------|--------------------------------------|---------|
| `meters_per_tile` | metres per tile edge                 | 5       |
| `alt_max`         | ceiling, metres                      | 60      |

Arena size = map size × `meters_per_tile`, centred on NED (0, 0). Tile (0, 0) — the
top corner of the iso diamond — is the **north-east** corner; Tiled +x runs toward
−N and +y toward −E, so north is up-left and east is up-right on screen (matches the
viewer and the student guide).

## Layers

- **Tile layers** — terrain, drawn by the viewer only. Use CSV / plain-array data
  (no base64/zlib) and embedded or external tilesets with a single image.
- **Object layers** — gameplay geometry, parsed by the server (`app/game/tiled.py`):
  - **Points** with class `pad` (or on a layer named `pads`): spawn pads; property
    `slot` (int) picks the slot, else their order. Unauthored slots keep the default
    row along the south edge. Pads **snap to the nearest hex cell** — a pad is a cell,
    not a free point, so its marker always fills one lattice hex (the lattice is
    `HEX_SIZE` in `app/game/hex.py`, independent of the Tiled grid).
  - other **Points**: named points by object name — `dropoff` is used by the
    delivery mission.
  - **Rectangles / polygons / ellipses**: regions. `kind` = the object's class, else
    the layer name (`district`, `no_fly`, …); `id` = the object's name. Custom
    properties travel to missions and the viewer (`label`, `speed_limit`,
    `no_spawn`…). Regions are queryable via `WorldAPI.region_at(n, e)`; drones carry
    `region` in world frames and get `region_enter` / `region_exit` lifecycle events;
    crates never spawn in `no_fly` regions or where `no_spawn` is set.
  - A layer named `props` with **tile objects** places decorative sprites (the viewer
    renders them; the server ignores them).
